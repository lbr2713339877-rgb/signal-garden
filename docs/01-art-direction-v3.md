### 0.3 WebGL 与性能预算的张力（需要在设计阶段就约束）

「延迟加载 WebGL」和「首屏就是一个正在生成的数字空间」是矛盾的。解法写在第六节：**首屏信号场用 CSS/DOM 实现，WebGL 只负责首屏之后的那一个场景**。这样首屏不需要等 Three.js。

## 1. 视觉概念

### 一句话

**Signal Garden 是一个用来观察「什么东西正在生长」的空间，不是一个用来浏览项目清单的页面。**

### 概念的落点

「雷达」只存在于产品逻辑里，画面里永远不出现雷达。视觉上要表达的是一个更本质的东西：

> **信号是被测量出来的，所以信号看起来应该像被测量的样子。**

这句话是整套视觉的脊柱。它决定了：

- 项目不是一个带圆角的卡片，而是一个**被观测到的对象**——有位置、有深度、有质量、有存在时间。
- 热度不是一个绿色数字，而是**一条轨迹变亮的程度**。
- 「新发布」不是一个 NEW 标签，而是**一个刚刚出现、还没稳定的物体**。
- 风险不是红色警告框，而是**材质变冷、信息变克制**。
- 多源讨论不是四个 logo，而是**多个信号进入同一个实体**的过程。

### 用户在滚动时经历什么

整个首页是一次单向的**降噪过程**，用户不是在往下看内容，而是在看着噪音被逐层剥离：

```
噪音 ──→ 扫描 ──→ 聚合 ──→ 识别 ──→ 聚焦 ──→ 理解 ──→ 选择
```

关键：**页面本身在执行这个动作，而不是描述这个动作**。这是它区别于普通 AI 网站的根本原因。普通网站会写「我们用 AI 帮你筛选」，然后把这句话作为文案放在标题上；这里是把「筛选」做出来给用户看。

### 一个贯穿全页的参数

全页只有一个滚动进度参数 `t ∈ [0,1]`。所有 section 的视觉状态都是 `t` 的函数：

| 变量 | 随 t 变化 |
|---|---|
| 背景色温 | 偏冷的黑 → 略暖的黑 |
| 玻璃透明度 | 0.04 → 0.14 |
| 排版尺度 | 标题字号跨 section 连续变化，不是每屏重置 |
| 物体深度 | 景深从浅到深再到浅 |
| 光的数量 | 从多（噪音）到少（聚焦） |
| 文字裁切量 | 从切碎到完整 |

不是一个 section 一个动画，而是**同一条曲线在不同维度上的投影**。这是「叙事动效」和「滚动动画合集」的区别。

## 2. 首页完整 Storyboard

### Section 01 — 黑场与呼吸（0 → 100vh）

**目的**：建立空间，不是建立信息。用户第一眼看到的应该是「这里很安静」。

信息量被压到极低：

```
SIGNAL GARDEN
/ DAILY DISCOVERY SYSTEM
```

**加载编排**（约 2.4s，分 6 层，绝不一起淡入）：

| 层 | 内容 | 起止 | 动效 |
|---|---|---|---|
| 1 | 纯黑 `#030303` | 0 → 300ms | — |
| 2 | 一道极细光带从左边缘扫过 | 300 → 1500ms | 位移 + 透明度，12px 宽，`blur(2px)` |
| 3 | 标题的字形轮廓出现 | 700 → 1200ms | 描边可见，填充不可见 |
| 4 | 标题填满 | 1200 → 2000ms | 描边 → 实心，逐字 40ms 错开 |
| 5 | 系统信息层出现 | 1900 → 2300ms | 从下方 12px + 淡入 |
| 6 | 第一个信号对象进入视野 | 2300 → 2400ms | 从画面外缓慢进入 |

光带是**一束穿过玻璃的光**，不是粒子、不是星空、不是科技网格。它是整页唯一一次「一次性的、不可重播」的动效——用户刷新才会再看到，这让它像开场而不是装饰。

主标题最终形态：

```
Something new
is taking shape.
```

中文副标题：

```
每天，从全网新项目中筛出真正值得打开的部分。
```

**注意这里和 V2 的差别**：「is happening」改成「is taking shape」。前者是状态描述，后者是过程——一个字就决定了后面所有动效应该表达「形成」而不是「存在」。

### Section 02 — 信号正在生成（100vh → 220vh）

**目的**：让用户看到「有东西在被发现」，但还看不清是什么。

背景中 14 个对象（桌面端；移动端 6 个）。它们**不是发光小球**，每个对象从下列形态中选一种，且全页每个形态最多出现 3 次，避免视觉重复：

| 形态 | 实现 | 用途 |
|---|---|---|
| 透明几何切片 | CSS `clip-path` 多边形 + 低透明度填充 | 主体，占一半以上 |
| 模糊玻璃薄片 | `backdrop-filter: blur()` + 1px 边 | 靠近中心的对象 |
| 极细线条 | 1px，长度 40–200px，随机角度 | 边缘、远处 |
| 被裁切的字体片段 | 2–3 个大写字母，`overflow: hidden` 裁掉一半 | 2 个，作为记忆点 |
| 小型 UI 碎片 | 一个输入框轮廓、一个滚动条、一个按钮边缘 | 暗示「这是软件项目」 |

运动特征（这是「不要像屏保」的关键）：

- **速度分层**：三种速度，比例约 1 : 0.6 : 0.35
- **深度分层**：三种尺度（0.7 / 1.0 / 1.4），配合不同 `blur`
- **惯性**：对象响应滚动时有 200ms 延迟跟随，不是刚性绑定
- **微漂浮**：每个对象独立的 8–14s 正弦浮动，振幅 4–10px，绝不循环到能被察觉
- **有限随机**：位置在预设的 14 个锚点附近 ±8% 抖动，不是纯随机——纯随机会让每次刷新都不同，破坏「这是一个系统」的感觉

**这个 section 的动效表达什么**：表达「有很多东西在被扫描，但还不知道哪个重要」。所有对象同等亮度、同等饱和度、同等清晰度。**不分主次就是它的含义。**

滚动到 60% 时，画面出现：

```
01 / SIGNAL DETECTED
```

四个对象开始向彼此靠拢，其余 10 个逐渐降低对比度（不是消失，是退到背景里）。

滚动到 80% 时，靠拢的四个对象构成一个模糊的整体，标题出现：

```
BROWSER AUTOMATION SKILL
让 AI 真正操作浏览器。
```

数据以极小等宽字体从边缘进入：

```
GITHUB +328% / 24H
NEW / SKILL / CLAUDE CODE
```

### Section 03 — 多源聚合（220vh → 320vh）

**目的**：用视觉解释「一个项目为什么可信」。这是产品的信任基础。

不是四个 logo 卡片。四个源被做成**四种不同材质和节奏的信号**：

| 源 | 材质 | 节奏 | 颜色 |
|---|---|---|---|
| GitHub | 冷青玻璃片，边缘锐利 | 等距脉冲，最密 | `#73D9E8` |
| Hacker News | 琥珀橙细线，轻 | 不规则，讨论驱动 | `#DFA06B` |
| Product Hunt | 珊瑚粉薄膜，柔 | 一次性的起伏 | `#E98A9B` |
| Community | 雾蓝碎片，最弱 | 断续 | `#8997D6` |

它们沿四条**不同曲率**的轨道向中心移动，汇入一个项目实体。汇入瞬间，中心对象**从模糊变清晰**——这是全页第一次出现「清晰」的对象，用清晰度来表达「这就是信号」。

四条轨道的粒子密度不同：GitHub 那条约是另外三条之和的两倍。密度就是权重。

### Section 04 — The Signal / The Noise（320vh → 420vh）★ 核心 section

**目的**：这是产品价值的全部表达。如果只能保留一个 section，保留这个。

**前半段——噪音**：

七组词快速掠过，但**不能是滚动字幕**。每组的处理不同：

```
NEW TOOL      → 互相覆盖，后一个压住前一个
NEW MCP       → 被左侧裁切，只露一半
NEW AGENT     → 模糊到失焦（blur 0 → 7px）
NEW SKILL     → 短暂出现 80ms 后消失
NEW FRAMEWORK → 纵向拉伸变形（scaleY 1.4）
NEW WORKFLOW  → 被黑色遮罩从右向左吞没
NEW LAUNCH    → 重复出现三次，越来越淡
```

速度是**加速**的：出现间隔从 380ms 递减到 70ms。到后半段，文字已无法阅读，形成视觉噪音墙。

**转折点**（这一秒是整页的记忆点）：

所有内容在 **240ms 内**向画面正中心收缩到一个直径 2px 的点，同时背景从 `#0C0C0F` 压到 `#030303`。**画面完全静止 600ms**。什么都没有。

然后：

```
We kept the signal.
我们只留下真正值得看的部分。
```

**这个「停顿」是设计的一部分，不是等待**。在一个到处都在动的页面里，静止是最强的表达。它说的是：我们敢于什么都不给你看，因为给你的都是真的。

### Section 05 — 今日精选（420vh → 结尾）

**目的**：交付价值，同时保持叙事节奏。

不是 10 张等大卡片。是**项目档案切片系统**。每个项目占据一个接近满屏的区域，信息按 7 步依次出现：

| 步 | 内容 | 时间 | 位置 |
|---|---|---|---|
| 1 | 编号 `01` | 0ms | 左侧边缘，垂直排列 |
| 2 | 项目名称 | +120ms | 跨越屏幕，可超出视口右边缘 |
| 3 | 项目视觉 | +260ms | 占位 40%，偏右 |
| 4 | 一句话说明 | +420ms | 紧贴名称下方，最长 60 字 |
| 5 | 热度数据 | +560ms | 沿一条细线，线随数据增长被绘制 |
| 6 | 为什么值得看 | +700ms | 来自 hook |
| 7 | 查看项目 | +840ms | 右下 |

**项目之间不是滚动切换，是「剪出来」**：下一个项目从当前项目的内部区域切出（wipe），切出方向根据两个项目的分类色决定。

项目之间的视觉差异必须真实存在：

- 项目名称的字号随名称长度反比变化（短名称占更大字号）
- 项目视觉占位在 32%–48% 之间浮动，不是固定值
- 分类色只出现在边缘、数据和视觉对象的折射里，**不做底色**

## 4. 排版系统

### 字体栈

```
Display（拉丁）：Instrument Serif        — 单字重，高对比，编辑感
Display（中文）：Noto Serif SC 600       — 与 Instrument Serif 对比度匹配
Sans（拉丁）：  Geist Sans               — 中性克制，接近 Suisse 的立场
Sans（中文）：  Noto Sans SC 400/500
Mono：         IBM Plex Mono 400         — 档案感，轻微人文不规则
Accent：       LXGW WenKai               — 仅编辑性引用，不用于正文
```

中英混排的关键决策：**中文大标题一律用 Noto Serif SC**，不用无衬线。理由：Instrument Serif 的高对比度衬线如果旁边是中文无衬线，两种字体的「声音」会打架——一个在抒情，一个在说明。中文衬线能接住它，中英并置时才是一个声音。

### 层级（极端差异，比例悬殊）

| 层 | 字号 | 字距 | 行高 | 用途 |
|---|---|---|---|---|
| Display XL | `clamp(3.5rem, 13vw, 15rem)` | `-0.045em` | 0.9 | 首页主标题、项目名称 |
| Display L | `clamp(2rem, 5.5vw, 5rem)` | `-0.03em` | 0.95 | section 标题 |
| Editorial | `clamp(1.25rem, 2.2vw, 1.875rem)` | `-0.015em` | 1.35 | 一句话说明（衬线） |
| Body | `0.9375rem` | `0` | 1.75 | 正文 |
| System | `0.6875rem` | `0.14em`（大写） | 1.5 | 编号、日期、来源、状态 |
| Data | `0.75rem` | `0.02em` | 1.4 | 等宽数据 |

**最大与最小字号比约 21:1。** 普通 SaaS 网站这个比值通常是 3:1，这是「像编辑作品」和「像后台」的分界线。

### 排版即动效

排版本身承担动效，不是给排版加动效。四种手法：

1. **文字裁切**：项目名称允许超出视口右边缘被裁切，滚动时随 `t` 逐渐归位。
2. **跨栏标题**：标题跨越 12 栏网格的 8 栏，剩余 4 栏留给数据。
3. **垂直文字**：编号 `01` 和状态 `NEW` 竖排在视口左边缘，`writing-mode: vertical-rl`。
4. **字号连续变化**：项目名称从 section 03 到 section 05 连续放大 1.6 倍，中途跨越两个 section，不做重置。

### 空白

section 之间最小间距 `clamp(96px, 18vh, 280px)`。首屏文字区左右各保留至少 30% 空。**空白是主色的一部分，不是剩余空间。**

## 5. 色彩与材质系统

### 背景（三层，够用）

```
#030303   黑场、section 04 的静止画面
#070709   默认页面底色
#0C0C0F   抬起面、玻璃底
```

### 文字

```
#F2F0EA                     主文字（不是纯白，带 2% 暖）
rgba(242,240,234,0.58)      次文字
rgba(242,240,234,0.32)      弱文字
```

主文字用暖白 `#F2F0EA` 而非 `#FFFFFF`：纯白在纯黑上会有辉光溢出感，暖白更像纸上印刷的墨。

### 环境光（六色）

```
电紫 #9C7CFF    冷青 #73D9E8    珊瑚粉 #E98A9B
琥珀橙 #DFA06B   薄荷绿 #9BC9A7   雾蓝 #8997D6
```

**这些颜色永远不作为填充色出现。** 允许的出现方式只有六种：

1. WebGL / Canvas 光源
2. 玻璃折射（`filter` 或 `mix-blend-mode`）
3. 半径 ≥ 200px、透明度 ≤ 0.14 的环境光斑
4. 1px 边缘高光
5. 直径 ≤ 6px 的状态点
6. 文字/图形的短暂染色（停留 ≤ 400ms）

**禁止清单**（出现即推翻重做）：紫蓝渐变背景、彩虹卡片、每组件一种鲜艳色、霓虹边框、持续闪烁、发光按钮、大面积荧光色。

### 材质：玻璃只有一个系统

三层，不允许第四层：

| 层 | 用途 | 规格 |
|---|---|---|
| Glass-1 | 静置面 | `rgba(255,255,255,0.04)` + `blur(24px) saturate(1.2)` + `1px rgba(255,255,255,0.06)` |
| Glass-2 | 悬停面 | `0.07` + 同上 + `1px rgba(255,255,255,0.12)` |
| Glass-3 | 焦平面 | `0.11` + `blur(40px)` + `1px rgba(255,255,255,0.18)` |

**圆角上限 4px。** 不做 12px / 16px / 20px 圆角。项目对象用切片、多边形、裁切，不用圆角矩形。

这条是「不像 AI 工具导航站」最有效的单一约束。圆角大卡片是 AI 生成站点的视觉指纹。

## 6. WebGL 使用计划

### 原则

**首屏不用 WebGL。** 首屏的信号场用 DOM + CSS 实现（`clip-path` + `backdrop-filter` + `transform`）。原因：Three.js 的包体和初始化时间会直接吃掉 LCP 预算，而首屏只需要「飘动和模糊」——CSS 完全够用，且能 60fps。

WebGL 只负责**一个场景**，在首屏之后空闲时加载。

### 那一个场景承担什么功能

**不是装饰。它承担「发现」这个动作本身**：Section 02 末尾到 Section 03 之间，信号对象从「14 个无关的碎片」到「4 个聚合成一个实体」的整个过程。

具体：

- 14 个平面（`PlaneGeometry` + 自定义 shader），半透明，不同深度
- 顶点着色器加入低频噪声位移（simplex noise，速度 0.02），产生「材质在呼吸」的感觉
- 片元着色器做**基于视角的折射**：用背面渲染的简单做法，不引入额外 render target
- 光照：3 个低强度点光源，颜色取自环境光六色中的三个
- 汇聚：每个平面的 position 用 `t` 插值到目标位置，目标位置在球面均匀分布

明确不做：

- 旋转地球、星空、赛博网格地面
- 粒子爆炸
- 反光金属球
- 与内容无关的抽象技术秀

### 降级策略（三级）

| 级别 | 触发条件 | 表现 |
|---|---|---|
| Full | 桌面 + `devicePixelRatio ≤ 2` + 非 `prefers-reduced-motion` | 14 平面 + 折射 + 噪声位移 |
| Reduced | 移动端，或低端设备（`hardwareConcurrency ≤ 4`） | 8 平面 + 无折射 + 静态纹理 |
| None | `prefers-reduced-motion`，或 WebGL 不可用，或省流模式 | 纯 CSS 模糊光斑 + 静态布局，**信息零损失** |

`None` 级别不是「网页坏了」——Section 02 的 14 个对象在 `None` 下变成静态的 CSS 玻璃切片，位置和颜色完全一致，只是不移动。用户看到的内容一模一样。

## 7. 页面转场方案

### 首页 → 详情页：共享元素

项目名称和项目视觉对象共同构成共享元素。用户点击后：

1. 卡片上的项目名称开始放大并移动到详情页标题位置（`view-transition-name` 或 Framer Motion `layoutId`）
2. 背景不是切换，是**相机推进**：`scale` 从 1 → 1.06，同时 `opacity` 降到 0.3
3. 详情页从 0.94 放大到 1，`opacity` 0 → 1
4. 中间有 120ms 的**黑场闪烁**（`#030303` 覆盖），让转场有快门感

时长 780ms。不支持 View Transitions API 的浏览器直接切换，不报错、不降级动画——**承认浏览器差异比做一个假的转场好**。

### 分类切换：空间变色

切换分类不是替换列表，是**同一个空间的物理状态改变**：

| 阶段 | 时长 | 变化 |
|---|---|---|
| 1 | 0 → 200ms | 当前列表对象降低对比度至 0.35，轻微后撤（`scale 0.98`） |
| 2 | 200 → 500ms | 环境光颜色插值到新分类色；背景色温变化 |
| 3 | 500 → 800ms | 新对象从背景深度进入，前 40% 更亮 |
| 4 | 800ms | 稳定 |

标题不做「淡出淡入」，做**字形变形**：旧标题的字形组件被拉长并位移出，新标题的字形组件从同一位置拉伸进入。用 `clip-path` + `scale` 在两个标题之间做 400ms 的形变。

### 详情页 → 返回：逆向但更快

返回用 420ms，比进入快 46%。**进入慢、返回快**是一个不被注意但影响很大的细节——用户返回时已经知道要去哪，不需要再被叙事一次。

## 8. 分类视觉映射（6 个空间状态）

6 个一级分类对应 6 种空间状态。每个二级分类是在父级空间内的**局部偏移**——切换二级时，
环境光的色相不变，但饱和度、模糊半径和运动节奏会轻微移动，让用户感到「还在同一个房间里，
换了一个角落」，而不是跳进另一个空间。

| 一级分类 | 环境色 | 材质 | 运动节奏 | 版式倾向 |
|---|---|---|---|---|
| AI 工具 | 电紫 `#9C7CFF` | 深色光晕，边界模糊 | 缓慢、有重量 | 大标题，少文字 |
| 独立站与出海 | 冷青 `#73D9E8` | 锐利冷玻璃，1px 硬边 | 等距、精确 | 数据密，编号醒目 |
| 开发者工具 | 雾蓝 `#8997D6` | 半透明层叠，低对比 | 快速切入 | 等宽为主，网格化 |
| 设计资源 | 珊瑚粉 `#E98A9B` | 柔和平滑，无硬边 | 轻、连续 | 大留白，衬线为主 |
| Skill 与 Agent | 薄荷绿 `#9BC9A7` | 潮湿感，高光弱 | 断续、有惯性 | 紧凑，切片式 |
| 效率应用 | 琥珀橙 `#DFA06B` | 纸质哑光，无反射 | 短促、克制 | 列表，密集 |

### 二级分类的空间偏移

| 二级 | 父级 | 偏移 |
|---|---|---|
| browser | Skill 与 Agent | 加入窗口框、指针轨迹、坐标标签；运动改为断续 + 惯性 |
| data | 开发者工具 | 网格显露，透明度降低，等宽密度提高 |
| security | 开发者工具 | 饱和度 −60%，亮度 −40%，改为冷白 `#E8ECEF`，近乎静止 |
| motion | 设计资源 | 振幅放大，运动连续不中断，其他元素降对比 |
| cost | 效率应用 | 排版收窄，数字层放大，其余元素退后 |
| landing | 独立站与出海 | 出现横向分栏和首屏矩形，暗示页面结构 |

### 最小验证

**设计资源与开发者工具必须一眼能区分。** 这两个如果看起来像同一个空间，
说明环境色和材质的差异做得不够，整个分类系统不成立。

具体差异：珊瑚粉是**柔和平滑 + 大留白 + 衬线**，雾蓝是**层叠半透明 + 网格化 + 等宽**。
一个在抒情，一个在说明。这是最容易混淆的一对，也是最该先验证的一对。

## 9. 项目详情页 Storyboard

### 第一屏 — 抽象场景（不写数据）

左：项目名称（Display XL，跨越到屏幕中部）
下方：一句话说明（Editorial，衬线）
背景：Canvas 2D 完成的抽象场景，循环 18s

**场景内容按项目能力生成，不是通用动效。** 例：Browser 类项目的场景是「窗口层叠 → 页面结构出现 → 指针移动 → 表单填充 → 结果提取」，用简单几何和 1px 线完成，**不做完整浏览器模拟器**。Design 类项目的场景是「画板层叠 → 网格出现 → 元素对齐 → 色板展开」。

场景是**能力的**视觉化，不是装饰。用户应该在没读文案前就大致猜到它能做什么。

### 第二屏 — Why now（数据分布，不是卡片）

```
FIRST SEEN     24 SEP 2026     ← 贴在左边缘，垂直排列
GROWTH         +328% / 24H     ← 沿一条线，线随数值长度绘制
DISCUSSION     3 SOURCES       ← 沿轨道排列的 3 个点
STATUS         ACTIVE          ← 一个 4s 周期的呼吸点
```

滚动时依次激活（间隔 140ms）。**数据不是四张卡片**，是分布在空间里的四个观测值。

### 第三屏 — What it does（动作分镜）

3–5 个动作，每个一个小型动效（≤ 600ms）：

```
READ      → 线条扫描过一片文字区域
UNDERSTAND→ 结构从散乱对齐到网格
ACT       → 一个指针移动到目标并点击
EXTRACT   → 目标区域被框选并分离出来
RETURN    → 结果被收拢并归位
```

### 第四屏 — Who it's for（场景，不是头像）

不用头像卡片。用**局部空间**：每个身份对应一小块抽象场景。

```
Independent builders  → 一个人的工作台：一个屏幕、一个窗口
AI product teams      → 三个窗口并置，其中一个在更新
Automation makers     → 一条流水线，有节点和箭头
```

**必须是抽象场景，不能是真人照片，不能是真实公司或职位。** 这一块在 V2 里已经定了规则，V3 保持不变，只把视觉从卡片换成空间。

### 第五屏 — Install（真实工具感）

黑色终端平面 + 玻璃边缘 + 逐字出现的命令（每字 18ms，总共不超过 1.2s）。
复制后：按钮文字切换 + 终端出现一行的成功状态（绿色 `#9BC9A7` 的细线从左扫过）+ 2s 后回落。**不是弹 toast。**

### 第六屏 — Limits / Risk（可信度的一部分）

```
NEEDS LOCAL RUNTIME
REQUIRES API KEY
BROWSER ACCESS
EARLY STAGE
```

不用警告弹窗、不用红色。风险表达方式：**材质变冷**（环境光饱和度降低 60%、亮度降低 40%），**排版变克制**（字号回到 System 层、字距加大），**结构变规则**（编号、缩进、等宽）。

**风险不是给用户看的警告，是产品的可信度证据。**

## 10. 桌面端与移动端差异

不是缩放，是两套不同的叙事。

| 维度 | 桌面 | 移动 |
|---|---|---|

## 11. Reduced-Motion 版本

`prefers-reduced-motion: reduce` 不是一个「关掉动画」的开关，是**一套完整的替代方案**。

| 元素 | 正常 | Reduced |
|---|---|---|
| 光带 | 横扫 1.2s | 不出现 |
| 标题 | 分层填充 | 直接显示，200ms 淡入 |
| 信号场 | 14 个对象漂浮 | **静态**，位置与颜色不变 |
| WebGL 场景 | 顶点位移 + 折射 | 不加载，改静态 CSS 玻璃切片 |
| 噪音墙 | 加速 + 变形 + 失焦 | 静态三行文字 + 直接显示结论 |
| 收缩转折 | 240ms 收缩 + 600ms 静止 | 直接黑场 400ms |
| 项目切片 | 7 步递进 | 一次性显示，200ms 淡入 |
| 分类切换 | 800ms 空间变色 | 200ms 交叉淡入 |
| 共享元素转场 | 780ms | 直接切换 |
| 数字滚动 | 0 → N 计数 | 直接显示终值 |
| hover | 上浮 + 材质变化 | 只改边框颜色 |

**核心约束：Reduced 版本的信息量与完整版完全相同。** 少了动效，不能少任何一条数据、任何一个项目、任何一条风险提示。

## 12. 技术风险与性能预算

### 预算（可测量的硬指标）

| 指标 | 目标 | 红线 |
|---|---|---|
| LCP（桌面 M 系） | < 1.8s | 2.5s |
| LCP（移动 4G） | < 2.4s | 3.0s |
| CLS | < 0.02 | 0.1 |
| INP | < 150ms | 200ms |
| Three.js 包体 | ≤ 150KB gzip，**首屏后加载** | 180KB |
| 首屏 JS（不含 WebGL） | ≤ 90KB | 120KB |
| 帧率（桌面） | 60fps | 45fps |
| 帧率（移动） | 30fps | 24fps |
| 字体加载 | 仅预载 Display 一层，其余 `font-display: swap` | — |

### 硬性技术约束

- 动画只用 `transform` 和 `opacity`。**任何会触发 layout 的属性都不允许出现在动画里。**
- 只有一个 WebGL canvas，全页复用。
- `devicePixelRatio` 上限：桌面 2，移动 1.5。
- `visibilitychange` 时暂停所有 `requestAnimationFrame` 和 CSS 动画。
- 图片用 AVIF/WebP，项目截图走 GitHub 的 OG 卡片（GitHub 自产，不抓取他人站点）。
- 滚动动画使用 `IntersectionObserver` + `scroll` 的 `passive` 监听，不引第三方平滑滚动库（Lenis 会带来输入延迟和 12KB 成本；用原生 `scroll-behavior` + `rAF` 节流足够）。

### 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 中文字体体积（Noto Serif SC 全量 > 8MB） | 首屏被字体阻塞 | 只用 `unicode-range` 分片加载；或首屏中文改用系统衬线兜底（macOS: Songti SC），Noto 异步替换 |
| 极端字号在 320px 宽度下溢出 | 布局断裂 | 所有 Display 层用 `clamp()` 且下限 ≤ 2rem |
| GPU 机型差异导致 shader 编译失败 | 场景空白 | shader 编译失败捕获后直接降级到 `None` 级，不报错 |
| 60fps 目标与 14 个 `backdrop-filter` 对象冲突 | 滚动卡顿 | 首屏 `backdrop-filter` 对象上限 4 个，其余用 `clip-path` + 半透明填充伪造 |
| View Transitions API 支持不全 | 转场不一致 | 按能力检测，不支持就直接切换（第七节已定） |

## 14. 三个方向，及最终决定

**决定记录：采用方向 B（THE LIGHT FIELD / 光的现场）。**
采纳 A 的编号索引纪律，采纳 C 的噪音墙地层排布逻辑。

### 方向 A — THE ARCHIVE / 档案馆

**性格**：冷、干、学术。接近一本印刷的目录册。
**视觉**：不用玻璃，用纸。底色改为 `#0A0A0A` 上的暖灰面板。大量编号、索引、脚注。颜色几乎不用，只有冷白和一档极暗的琥珀。
**运动**：几乎不动。只有翻页和排版重排。节奏极慢。
**优点**：可信度最高，像专业数据库，绝不会被误认为 AI 生成。
**缺点**：与「发现」这个动作的情感不符——档案是回看，不是发现。而且弱化了增长这个核心数据。

### 方向 B — THE LIGHT FIELD / 光的现场 ★ 选择

**性格**：空间、材料、光。接近一个暗房展览。
**视觉**：黑色展场，彩色只作为穿过玻璃的光。玻璃三层，硬边裁切，圆角 ≤ 4px。排版极端，字号差 21:1。
**运动**：全页一个滚动参数驱动，叙事 > 装饰。
**优点**：最能表达「正在发现」；颜色的克制用法让它同时具备高级感和识别度；WebGL 有明确功能（聚合过程），不是炫技；分类切换有天然的空间语言。
**缺点**：性能预算紧张；WebGL 降级路径必须做扎实，否则中低端设备体验会塌。

### 方向 C — SIGNAL STRATA / 信号地层

**性格**：地质、层积、考古。
**视觉**：把「历史」做成视觉主体——每个项目是一层地层切片，滚动等于向下挖掘。用噪声纹理和深度阴影代替光。
**运动**：以「层」为单位位移，有重量感和摩擦感。
**优点**：「回溯机制」和「首次追踪」这两个概念有天然的视觉对应；不需要 WebGL。
**缺点**：与「今日精选」的时效性矛盾——地层暗示的是过去，而产品核心是今天。而且深度阴影在纯黑背景上不容易做干净。

### 我的选择：B 为主干，采纳 A 的纪律与 C 的一层

选 **B**。理由：

1. **它最直接地表达产品的核心动作**（发现、聚合、降噪），而 A 表达的是归档、C 表达的是历史。
2. **光的克制用法天然满足「不像 AI 工具站」**——因为它的颜色几乎不落在容器上，只落在空间里。这从结构上杜绝了「彩虹卡片」。
3. **Section 04 的「收缩到黑」只有在有光的语境里才成立**。在 A 的档案语境里，那个转折会显得突兀。

从 A 采纳的：**编号、索引、脚注的纪律**。A 的 `01 / SIGNAL DETECTED` 这种系统层排版，是 B 的可信度来源。没有这一层，B 会滑向纯装饰。

从 C 采纳的：**Section 04 的噪音墙用「地层」逻辑排布**——不是散落，而是按时间一层层叠加、互相覆盖，最后被压缩。这让噪音墙有结构，不是随机堆叠。
